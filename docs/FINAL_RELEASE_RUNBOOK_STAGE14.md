## 4. План отката при ошибках

- **Только статический UI:** `install-static-release.sh` сохраняет `PREVIOUS_RELEASE` (при предыдущем symlink) либо `ROLLBACK_COPY` (при исходной директории). По отдельной команде администратора вернуть прежнюю ссылку/директорию атомарно, проверить Nginx/HTTPS и API-совместимость. Не удалять текущую сборку до фиксации инцидента.
- **Backend:** остановить новые записи/таймеры, сохранить аварийный snapshot, вернуть предыдущий совместимый код и конфигурацию; убедиться, что API совместим с текущей схемой. **Git rollback не отменяет финансовые операции, миграции и выплаты**.
- **PostgreSQL:** не откатывать схему автоматически. Зафиксировать последние операции, оценить совместимость, сделать дополнительный backup и отдельно согласовать восстановление/ручную коррекцию. Не затрагивать CRM `public`.
- **Webhook/outbox:** не удалять очередь ради отката. Проверить идемпотентность, lease/retry, сохранить непринятые события; изменение webhook — отдельная операция.
