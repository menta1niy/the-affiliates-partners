# iPhone Telegram WebView — клавиатура и упрощённая анкета

Дата: 2026-11-21. Исходные наблюдения: два скриншота Telegram Mini App на iPhone от владельца.

## Реализовано

- `web/telegram-layout.js`: скрытие плавающей навигации сразу при фокусе на поле, без зависимости от событий изменения высоты Telegram; касание вне поля и отдельная видимая кнопка «Готово» снимают фокус с цифрового поля; зафиксировано доступное расположение кнопки при некорректном/отсутствующем `visualViewport.resize`.
- `web/style.css`: док не рендерится, пока поле в фокусе; карточки, формы и радиокнопки имеют мобильный `max-width:100%`, `min-width:0`, `box-sizing:border-box`; нативное поле даты убрано из новой анкеты.
- `web/index.html` / `web/app.js`: вместо даты рождения и ручного ввода четырёх отдельных счётчиков — единый вопрос «Сколько у вас кредитных продуктов?» с вариантами **0**, **1–3**, **>3**. При регистрации и завершении анкеты существующего аккаунта участник подтверждает совершеннолетие и принятие документов. Для уже зарегистрированных пользователей предусмотрено обновление диапазона одним нажатием.
- Backend (`server/registration.py`, `server/profile.py`, `server/db.py`): принимает `credit_band` (`0`, `1-3`, `3+`) и `adult_confirmed=true`, не запрашивает и не выдумывает дату рождения или точные числовые счётчики. Проверяет корректный диапазон и согласия. Сохраняет поддержку старых регистраций с датой рождения/детальными счётчиками; возрастное ограничение для существующих анкет действует по ранее сохранённой дате, для новых — по явному подтверждению совершеннолетия.
- PostgreSQL/SQLite: два аддитивных поля `registration_profiles.credit_band`, `registration_profiles.adult_confirmed`, без удаления/перезаписи старых анкет. Производственная миграция: `deployment/mvp-schema.sql` (`ALTER TABLE ... ADD COLUMN IF NOT EXISTS`).
- Тексты о составе данных в трёх юридических HTML-страницах приведены в соответствие с новой формой и ранее сохранёнными анкетами.

## Приёмка до публикации

- Серверная регистрация и профиль: **54 теста**, успешно.
- Браузерные мобильные проверки: **8 тестов**, успешно (включая четырёхширинный набор 320/375/390/430 px).
- Дополнительные регрессии регистрации, приглашений и офферов: **56 тестов**, успешно.
- На изолированном PostgreSQL 17 выполнено копирование синтетической SQLite-схемы и данных; новый `deployment/mvp-schema.sql` применён с `ON_ERROR_STOP=1`, `database.postgres.validate_ready` подтверждает обе новые колонки.
- Это локальные автоматизированные проверки, не ручной повторный аудит реального iPhone после публикации.

## Порядок релиза

1. Зафиксировать commit и синхронизировать GitHub. На Aeza убедиться, что действующие API и CRM здоровы.
2. Создать полный защищённый `pg_dump` и восстановить в одноразовую базу для проверки.
3. Создать резервную копию действующего backend, env и статического symlink target; не трогать Fernet key и секреты.
4. Применить аддитивный `deployment/mvp-schema.sql` через `psql -X -v ON_ERROR_STOP=1`; проверить `partners.registration_profiles`.
5. Согласованно заменить backend и статический архив проверенного commit; проверить `/api/health`, `/api/v1/health`, публичные страницы и авторизационные ограничения. При ошибке немедленно восстановить прежнюю пару backend/frontend; данные и Fernet key не удалять.
