# Partners — самостоятельный MVP без CRM Team

**Назначение:** один работающий Telegram-кабинет участника и одна админка.
Стартовый вариант не создаёт CRM-workspace, не подтверждает банковские операции
и не публикует реальные финансовые начисления.

## Что получает администратор

- Участники идентифицируются по Telegram username или Telegram ID; номер
  телефона не используется, так как Telegram WebApp не предоставляет его
  без отдельного согласия и запроса контакта.
- «Каталог офферов»: создание и редактирование названия, категории,
  целевого действия, оплаты в рублях, холда в днях, инструкции и HTTPS-ссылки.
- Внутри карточки участника: назначение/снятие оффера, ручной статус,
  комментарий, статистика. Статусы: назначено, в работе, на проверке,
  завершено, отклонено. Все действия защищены Telegram initData, ролями,
  агентской областью видимости и записываются в журнал аудита.
- Создание/редактирование общего каталога доступно только владельцу.
  Агентский администратор может назначать существующие офферы лишь своим лидам.

## Что получает участник

- Открытая заявка по подписанной Telegram-сессии с подтверждённым согласием,
  затем одобрение администратором. До одобрения офферы не видны.
- Свои назначенные офферы: оплата, холд, категория, целевое действие,
  инструкция и ссылка; история ручного статуса в виде текущего состояния,
  комментарий администратора и сводка по количеству назначений.

## Production включение

1. Проверить резервные копии и существующую таблицу `partners.users`.
2. Установить **только** `deployment/mvp-schema.sql` в существующую БД через
   владельца схемы PostgreSQL. Не применять CRM-миграции.
3. Развернуть API + статические файлы одного проверенного коммита;
   `server/db.initialize` при `PARTNERS_PG_SCHEMA_READY=true` проверит обе
   таблицы и доступ к ним без DDL.
4. В защищённом `/etc/the-affiliates-partners/partners.env` включить
   `PARTNERS_MVP_OPEN_REGISTRATION=true`; сохранить прежнюю копию окружения
   с прежними правами без вывода секретов в лог.
5. Подключить Telegram Mini App через меню официального бота и проверить
   настоящий Telegram `initData`, реальное одобрение, выдачу оффера и статус.

Не включать CRM outbox или финансовые операции для этого MVP. Когда появится
CRM `Team`, ручные MVP-назначения нужно будет сопоставить с официальными
заявками отдельно, без автоматического признания оплаты.
