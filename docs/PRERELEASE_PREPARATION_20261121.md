# The Affiliates Partners v3.2 — дополнительные предрелизные испытания

**Дата:** 21 ноября 2026. **Ветка:** `feature/green-theme-20261114`. **База:** `21c56472747bf5bf7258c71667ea053702484162`. **Режим:** исключительно локально, без GitHub/Aeza и без production-данных.

## Решение владельца по реквизитам

Владелец распорядился **не указывать юридические реквизиты**. Настоящая подготовка не заполняет реквизиты, не создаёт фиктивного оператора, даты одобрения, юридические утверждения либо `deployment/legal-approval.json`. Пять юридических HTML-документов остаются внутренними проектами. Независимо от продуктового пожелания отсутствие обязательных сведений об операторе и фактическом порядке обработки данных **не позволяет удостоверить соответствие требованиям закона и объявить публичный запуск юридически готовым**. Не обходить установленный fail-closed release gate.

## Устаревший деплой

Обнаружен критический обход защиты в историческом `deployment/deploy.sh`: его прямой `git fetch origin main`, `git merge`, копирование `web/` и включение таймеров не требовали юридически проверенного статического пакета. Скрипт выведен из эксплуатации ранним `exit 1` **до** любых операций. Нельзя использовать его в production даже после утверждения юридических документов; для будущего разрешённого релиза предусмотрен `docs/FINAL_RELEASE_RUNBOOK_STAGE14.md` и `deployment/install-static-release.sh`. Нельзя включать legacy deploy timer.

## Незакрытые условия

1. Реальные Telegram WebView iOS/Android: подписанная авторизация, возрастные ограничения, анкета, офферы, MFO, документы, история, рефералы, блогеры, финансы, ошибки сети и доставка outbox.
2. Сквозная совместимость Partners ↔ актуальная CRM/контракт API: тестовый `D:\GPT\Website\backend` оказался устаревшим. Совместимый исходный код найден в `D:\GPT\.crm-aeza-bootstrap-20261114\backend`; на чистой отдельной базе из пяти E2E два пройдены и три не прошли (`failed>=3` получено 1; snapshot `[1,2]` получено `[1,1,2]`; outbox `failed=1`, HTTP 409). Причина пока не установлена: возможна общая БД между сценариями. Не устранять проблему ослаблением assertions; проверить по отдельности и совместимость с действующей версией CRM.
3. Документированное подтверждение об операторе данных, правовых основаниях, хранении и прочих обязательных сведениях — не заменяется нулевыми реквизитами, текстом бренда или техническим тестом.
4. Production backup/restore, TLS/webhook, состояние таймеров, deploy/cutover требуют отдельного разрешения на доступ. Никаких команд деплоя или push в рамках этой проверки.

**Вывод:** можно продолжать локальную подготовку и устранение обнаруженных технических проблем. Релиз по-прежнему заблокирован до закрытия внешних условий и отдельного решения владельца.
