## Решение владельца по реквизитам

**Обновление решения:** владелец предоставил ФИО, ИНН, ОГРН и адрес для размещения в пяти юридических документах, после чего поручил подготовить редакции без маркировки «тестовый шаблон» и рассмотреть возможность релиза. Реквизиты внесены, маркеры проектов удалены. Принадлежность ИНН/ОГРН названному лицу и его правовой статус не установлены, а сроки хранения, условия выплат, порядок обработки данных и утверждение документации не подтверждены. `deployment/legal-approval.json` не создавался; действующий fail-closed release gate сохранён.

## Устаревший деплой

Обнаружен критический обход защиты в историческом `deployment/deploy.sh`: его прямой `git fetch origin main`, `git merge`, копирование `web/` и включение таймеров не требовали юридически проверенного статического пакета. Скрипт выведен из эксплуатации ранним `exit 1` **до** любых операций. Нельзя использовать его в production даже после утверждения юридических документов; для будущего разрешённого релиза предусмотрен `docs/FINAL_RELEASE_RUNBOOK_STAGE14.md` и `deployment/install-static-release.sh`. Нельзя включать legacy deploy timer.

## Незакрытые условия

1. Реальные Telegram WebView iOS/Android: подписанная авторизация, возрастные ограничения, анкета, офферы, MFO, документы, история, рефералы, блогеры, финансы, ошибки сети и доставка outbox.
2. Сквозная совместимость Partners ↔ действующей CRM/контракт API: локальный `D:\GPT\Website\backend` устарел, совместимый код найден в `D:\GPT\.crm-aeza-bootstrap-20261114\backend`. Все три ранее упавших сценария **прошли в изоляции**, но версия backend, фактически работающая на Aeza, не проверена и её обновление требует отдельного release-пути. Общий E2E запуск не должен повторно использовать одну синтетическую БД без очистки/изоляции.
3. Документированное подтверждение об операторе данных, правовых основаниях, хранении и прочих обязательных сведениях — не заменяется нулевыми реквизитами, текстом бренда или техническим тестом.
4. Production backup/restore, TLS/webhook, состояние таймеров, deploy/cutover остались непроверенными: SSH с текущей машины отклонён по `publickey`. **До любого GitHub push необходимо подтвердить отключение старого автодеплой-таймера непосредственно на Aeza.** Пользователь разрешил релиз при завершённом аудите, но условия до сих пор не выполнены; никаких команд deploy/push в рамках этой проверки не выполнялось. См. `docs/PRODUCTION_DEPLOYMENT_READINESS_20261121.md`.
