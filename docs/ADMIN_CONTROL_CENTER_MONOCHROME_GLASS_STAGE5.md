**Luxury Monochrome Control Center:** почти чёрный фон, графитовые рабочие панели, малоконтрастные прозрачные слои, направленный белый свет по кромкам, одна доминирующая белая CTA в Hero и крупные заголовки Plus Jakarta Sans.

Hero использует оригинальную лёгкую SVG-геометрию — не копию короны из исходного референса. Никаких фиктивных графиков, доходов, балансов или чисел в production.

### Мобильные данные без потерь

На экранах до 740 px данные таблиц преобразуются в вертикальные карточки посредством CSS; каждая `td` получает `data-label` на основе уже существующей колонки. Это презентационный атрибут, который **не влияет на API, HTML-таблицу в DOM, роль пользователя, действие или тестовые селекторы**. На десктопе таблица сохраняет полноту столбцов и допускает горизонтальную прокрутку внутри блока при необходимости.

### Особенности профиля

Основное управление остаётся внутри карточки участника. Для назначений отдельно оформлены:

- Название/категория/условия оффера;
- Реальные KPI ручных назначений;
- Селектор стадии;
- Комментарий;
- «Сохранить статус», «Убрать оффер» с прежним подтверждением, «Назначить оффер»;
- Одобрение ожидающего участника;
- История действий и CRM-секции при наличии CRM lead binding.

Вместо переопределения внутренней логики изменены только контейнеры, текстовые метки и CSS-классы.

## Безопасность и семантика

- После отсутствующей/невалидной Telegram-сессии не показываются админские кнопки; серверная проверка не менялась.
- Роли staff/admin/owner и фактический scope продолжают определяться сервером.
- Каталог owner-only для записи; admin читает каталог, но не видит форму его изменения.
- Оплата оффера — `payout_rub`, **не подтверждение банком или платёж**. Стадия `completed` остаётся ручной отметкой.
- Данные от API в динамической разметке передаются через `textContent`, новые небезопасные HTML-injection пути не созданы.
- Сохраняются текущие подтверждения `window.confirm` / `window.prompt` и все бизнес-проверки. Их возможная UX-замена выходит за пределы этапа 5.
