# The Affiliates Partners — этап 7/14: статусы лида, доказательства и МФО

Реализация только локальная в feature/green-theme-20261114. Ни GitHub,
ни Aeza, ни production-база до окончания 14 этапов не изменяются.

## Пользовательский сценарий

Администратор выбирает доступные для лида этапы отдельно в каждом
оффере: «Отправил заявку», «Назначена встреча», «Продукт получен»,
«Счёт открыт», «Займ получен». В кабинете лида отображаются только
разрешённые этапы. Лид отправляет выбранную отметку, приложив
HTTPS-ссылку, скриншот или оба доказательства одновременно.
Хотя бы одно подтверждение обязательно.

Изображения PNG/JPEG/WebP сжимаются на клиенте до 1280 px, а сервер
повторно проверяет формат, размер и отсутствие анимации, удаляет EXIF,
сохраняет WebP не более 550 КБ и шифрует байты перед записью в БД.
Открытых URL для этих скриншотов нет.

После отправки возникает заявка на рассмотрении. Пока она в работе,
нельзя подавать дубликат для того же оффера. При отказе менеджер
указывает причину, после которой лид может отправить отчёт повторно.
Подтверждённый этап повторно не отправляется.

Категория МФО, микрозайм или микрокредит получает кнопку «Запросить
оффер». Даже при заполненных ФИО/ИНН, совершеннолетии и актуальной
анкете URL оформления скрыт сервером, пока менеджер не одобрит
соответствующий запрос. При отказе запрос можно повторить.

## Финансовые границы

Новая таблица manual_offer_events хранит независимые от банковских
статусы проверки pending/approved/rejected. Одобрение МФО переводит
ручное назначение только в in_progress, одобрение отчёта — в submitted.
Не изменяются банковские credited/paid, CRM и реальные выплаты.
Стадия completed автоматически не выставляется.

## API и права

Все маршруты POST требуют проверенного Telegram initData:

- /api/mvp/submit: stage с offer_id, lead_stage, proof_url, screenshot
  либо mfo_request с offer_id.
- /api/mvp/my-events: последние 100 собственных событий без бинарных
  доказательств.
- /api/admin/mvp/events: очередь с фильтром pending, approved, rejected
  или all, ограничена своим агентством / закреплёнными менеджеру лидами.
- /api/admin/mvp/review-event: решение approve или reject, при отказе
  обязательна причина. Повторное решение возвращает 409.
- /api/admin/mvp/evidence: приватный скриншот только после проверки
  прав owner/admin/staff на конкретного лида; используется POST и
  зашифрованные данные на диске, публичного GET нет.

Отдельный шифровальный ключ PARTNERS_PROFILE_ENCRYPTION_KEY используется
для Fernet-шифрования доказательств и реквизитов. Его нельзя коммитить
или терять при переносе/восстановлении БД.

Telegram-outbox получает события: лиду — заявка отправлена и решение;
владельцу и закреплённому менеджеру — новый результат. Персональные
скриншоты и финансовая анкета в уведомления не включаются.

## БД и миграции

Новая таблица manual_offer_events: id, telegram_id, offer_id, kind,
lead_stage, proof_url, evidence_data, evidence_type, review_status,
review_note, reviewed_by, created_at, reviewed_at.

Индексы: ix_manual_offer_events_user и ix_manual_offer_events_review.
DDL PostgreSQL и GRANT добавлены в deployment/mvp-schema.sql,
runtime-schema-gate — database/postgres.py. SQLite создаёт таблицу
локально; перенос SQLite→PG обновлён.

Перед финальным релизом: резервная копия и проверка восстановления,
миграции этапов 3/5/6/7, Pillow/WebP, cryptography, защищённый ключ
Fernet, юридические сроки хранения/удаления скриншотов и доступов.
Не запускать автодеплой.

## Дизайн

Модальная форма лида содержит список разрешённых этапов, поле ссылки
и загрузку изображения. Карточка показывает последнее состояние
рассмотрения. Для МФО отдельное согласование, серая кнопка при
недоступности по возрасту или профилю.

В админке «Пользователи → Проверка офферов» есть фильтр состояний,
просмотр доказательств, комментарий, одобрение/отклонение. Раздел
доступен owner/admin/staff со scoped RBAC. Мобильные размеры 320/390,
области нажатия 44+ px, стиль Amber Edition.
