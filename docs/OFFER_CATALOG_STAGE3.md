# The Affiliates Partners — этап 3/14: каталог офферов

Реализовано локально по согласованному мастер-плану v3.2. Производственный
сервер и GitHub не затрагиваются до окончания всех этапов.

## Функции

- В редакторе оффера: загрузка PNG/JPEG/WebP с предпросмотром, удаление
  изображения, шаблоны этапов по категориям и ручная настройка этапов.
- Исходный файл до 5 МБ сжимается браузером в WebP 960 px. Сервер независимо
  проверяет реальный формат, запрещает SVG, анимации, размеры более 8 млн
  пикселей и данные больше 1 МБ. Финальный WebP не больше 250 КБ.
- Изображения хранятся в БД в таблице offer_logos, ключ — SHA256 содержимого.
  Карточки получают только logo_url. Брендовые логотипы доступны по
  публичному GET /api/offer-logo/<sha256>; личные данные не отдаёт.
- Карточки лида и админки показывают логотип фоном с непрозрачностью 15%.
- Дебетовые/кредитные карты и бизнес-счета: шаблон «Отправил заявку»,
  «Назначена встреча», «Продукт получен»; МФО: «Отправил заявку»,
  «Займ получен». Этапы можно изменить вручную.
- В подробностях оффера лид видит выбранный набор этапов. Возможность
  самостоятельно их отмечать относится к следующему этапу выполнения.
- Возрастной переключатель 14+/18+ и автоназначение не добавляются.

## Данные и выпуск backend

- Сохранение POST /api/admin/mvp/offer принимает lead_stages, logo_data
  и remove_logo. Редактирование по-прежнему доступно только владельцу.
- Каталог и обзор лида дополнены полями lead_stages и logo_url.
- Допустимый размер тела только этого POST — 1.5 МБ, для других — 24 КБ.
- SQLite использует добавочные ALTER TABLE. PostgreSQL требует выполнения
  deployment/mvp-schema.sql **перед** сменой backend: ALTER новых столбцов,
  CREATE TABLE offer_logos и GRANT роли ta-partners.
- Runtime-проверка PostgreSQL требует новую схему. Выпуск без миграции
  невозможен. Существующие назначения, роли и CRM не изменяются.
- На сервере обязателен Pillow с поддержкой WebP (проверить
  PIL.features.check('webp') в окружении службы до релиза).
- Изображения входят в стандартный бэкап базы; отдельный файловый runtime
  каталог не требуется.

## Защита и приёмка

- Не принимать невалидные base64/PNG, SVG, дубли и неизвестные коды этапов.
- При редактировании без новой загрузки старый логотип сохраняется.
- Прямой URL картинки не содержит сведений о лиде или выплатах.
- Проверить 320/390/430px, модальные окна, текст на фоне логотипа и длинные
  названия. Удалённое содержимое таблицы можно очищать отдельно, когда
  будет создан контролируемый механизм очистки неиспользуемых хешей.
- На сервер не публиковать до завершения всех этапов.
