# The Affiliates Partners — этап 6/14: реквизиты, возраст, кредитная анкета

Реализация локальная. Ветка feature/green-theme-20261114, без публикации
на GitHub и Aeza до завершения всех 14 этапов.

## Правила и UX

- После одобрения лидер/реферер заполняет в профиле фамилию, имя,
  необязательное отчество и **12-значный ИНН физического лица**. ИНН
  проверяется по двум контрольным разрядам. Сохраняется только после
  прохождения валидации; статус отображается в профиле.
- До завершения реквизитов все назначенные офферы **недоступны для
  оформления**. Просмотр карточек, условий и статуса не блокируется.
- Пользователям младше 18 лет недоступно оформление **любого** оффера.
  Никакого флага 14+/18+, исключений на два оффера и промежуточных
  возрастных статусов. Есть только «Доступно» / «Недоступно».
- Для кредитных карт, кредитов, ипотеки, рассрочек и МФО добавлена
  проверка свежести анкеты. Интервал актуальности — **30 дней**;
  затем в деталях отображается рекомендация перейти в профиль и
  обновить четыре показателя. Это условие локальной доступности,
  а не оценка банковского одобрения.
- В самом профиле анкета обновляется независимо от ФИО/ИНН и без
  смены даты рождения. Отображаются только объективные категории
  количества продуктов; никаких вымышленных процентов вероятности.
- Существующие аккаунты без новой анкеты могут заполнить её в профиле,
  включая дату рождения и согласия, **без повторной регистрации**.
  Внутренний ID и исходная реферальная атрибуция не меняются.
- Активным лидам доступна персональная реферальная ссылка, в том
  числе несовершеннолетним. Саморефералы по-прежнему запрещены.
  Будущие реферальные начисления 15% — отдельный этап.

## Защитная серверная граница

- POST /api/profile/identity: только подтверждённый lead/referrer.
  ФИО и ИНН шифруются **Fernet** и помещаются в новую таблицу
  participant_identities. В аудит не попадают личные значения.
- Секрет **PARTNERS_PROFILE_ENCRYPTION_KEY** — отдельный постоянный
  Fernet-ключ, не Telegram-токен. Его надо добавить в приватную
  конфигурацию runtime до финального релиза, с отдельным защищённым
  offsite-бэкапом ключа. Не коммитить и не выводить в логи.
- Потребуется установить пакет cryptography в серверное окружение.
  Если он или ключ отсутствует/неверен, операция сохранения
  возвращает 503, а старые зашифрованные записи не переоткрываются
  без оригинального ключа. Ротация ключа требует отдельной миграции.
- POST /api/session возвращает текущему пользователю расшифрованные
  компоненты ФИО, но только маску ИНН (последние 4 цифры). Полный
  ИНН не передаётся в общий список или уведомления.
- POST /api/profile/credit-survey: обновляет четыре числа 0–50
  только своему подтверждённому пользователю.
- POST /api/profile/onboarding: дозаполняет отсутствующую анкету
  старому подтверждённому пользователю с датой рождения, ответами,
  согласием и условиями. Однократная операция, без новой записи
  users, без уведомления о новой регистрации и без новых ID.
- GET-подобный авторизованный POST /api/mvp/overview вычисляет для
  каждого назначенного оффера can_apply и unavailable_reason
  (underage / identity / credit_review / registration). При запрете
  сервер **вообще не включает referral_url**, а не просто делает
  кнопку серой в клиентском HTML.
- Админский обзор назначения сохраняет право видеть оффер и условия.
  Никаких автоматических финансовых подтверждений не добавлено.

## Миграции

- SQLite создаёт participant_identities при initialize.
- PostgreSQL создаёт partners.participant_identities, grants runtime
  роли ta-partners в deployment/mvp-schema.sql, и проверяет готовность
  колонок через database/postgres.py.
- SQLite→Postgres copy учитывает новую таблицу.
- Перед финальным релизом: isolated backup и восстановление, add-only
  миграции этапов 3, 5, 6, установка cryptography/Pillow и WebP,
  проверка защищённого Fernet-ключа, затем переключение приложения.
  Автодеплой не включать.

## Приёмочные проверки

- Валидный ИНН и ФИО сохраняются, контрольные разряды проверяются.
- Без ФИО/ИНН, до 18 лет или при устаревшей кредитной анкете
  соответствующие банковские ссылки не выдаются сервером.
- После заполнения ФИО/ИНН взрослому доступен дебетовый оффер;
  кредитный разблокируется только после актуализации анкеты.
- Шифротекст в базе не содержит ФИО/ИНН. Неподтверждённые участники
  и пользователи без подписанного initData не могут записывать данные.
- Несовершеннолетний может приглашать, но не оформлять предложения.
- Мобильный браузер 320 и 390 px без горизонтальной прокрутки:
  реквизиты, анкета, заблокированные кнопки и переход в профиль.

## Предрелизное ограничение

Тексты условий этапа 5 — черновик, не готовое юридическое основание
для реальной обработки ФИО и ИНН. До публичного запуска обязательны
утверждённые документы по персональным данным, режиму хранения,
полномочиям сотрудников, срокам удаления и выплатам. Не вводить
реальные персональные данные в тестовые среды.
