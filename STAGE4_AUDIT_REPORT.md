# Этап 4 — техническая ревизия

Дата: 2026-10-31. Проверена отдельная feature-ветка, production не менялся.

## Независимая проверка
- Независимый read-only QA не нашёл обхода HMAC-подписи Telegram или неавторизованного доступа к admin API.
- Подтверждены дефекты автодеплоя: ранний выход после неудачного build при уже обновлённом HEAD, недостаточный перечень серверных изменений для перезапуска. Исправлено: отметка последнего успешно развёрнутого коммита, повторные попытки до успешного завершения, учёт всех файлов server/ и изменения сервисных unit.
- Подтверждён конфликт модерации: администратора допускали к одобрению пользователя без телефона, а API офферов этому пользователю возвращал 403. Теперь сервер отклоняет преждевременный аппрув; добавлен тест.
- Отдельно обнаружено, что шаблон .env.example был закоммичен с Telegram bot token. Значение удалено из рабочего дерева, но **остаётся в истории Git**. Обязательно перевыпустить токен в BotFather, обновить защищённое окружение VPS, исключить старый токен из использования. История Git этим изменением не переписывается.

## Проверки
- Python unittest: 21 тест прошёл. Проверены signed initData, права, сохранение профиля, повторный /start, контакт, модерация, офферы.
- TypeScript и Vite production build: успешно.
- Python compileall и git diff --check: успешно.
- Проверка git-tracked текстов на секретоподобные ключи после удаления из .env.example: новых совпадений не найдено.

## Ограничения
- Скрипт deploy не запускался на VPS; его новое поведение до production необходимо проверить на безопасной тестовой среде.
- Существующие /api/links, CRM conversions/analytics/payouts остаются неподключёнными и не являются завершённой функциональностью.
- Фронтенд не имеет браузерных end-to-end тестов на настоящем iPhone и Telegram, возможен race ответов при фоновом обновлении офферов.
- Интеграция CRM PostgreSQL с Telegram Partners SQLite не завершена.
